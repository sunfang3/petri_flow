# Dependency Upgrade Spec (Iteration 2)

Last updated: 2026-04-16

## 1. Scope

This spec covers **Phase 2 / Rails 7.2 track upgrade**.

Included:
- Constrain `rails` dependency to `< 8.0` and move to 7.2 line.
- Refresh lockfile to Rails 7.2 ecosystem.
- Fix test runtime incompatibility caused by `minitest 6` resolution.
- Validate with Ruby 3.2 runtime.

Excluded:
- Bootstrap/Select2 compatibility migration.
- Rails 8.x upgrade.

## 2. Files in Scope

- `wf.gemspec`
- `Gemfile`
- `Gemfile.lock`
- `test/dummy/db/schema.rb` (regenerated by migration run)

## 3. Requirements

### R1: Rails Constraint

- Gemspec must explicitly lock Rails into `>= 7.2, < 8.0`.

### R2: Lockfile Result

- Lockfile must resolve Rails to `7.2.x`.
- Core stack (`activesupport`, `activerecord`) must be on matching `7.2.x`.

### R3: Test Runtime Stability

- Pin `minitest` to `< 6` to avoid runtime API mismatch with current test runner setup.

### R4: Verification

- Use Ruby `3.2.9` to run:
  - `bundle install`
  - `bundle exec rubocop -V`
  - `bundle exec rails app:db:drop app:db:create app:db:migrate RAILS_ENV=test`
  - `bundle exec rails test`

## 4. Known Risks

- `bundle exec rake app:wf` depends on external `lola` download URL and currently fails due upstream URL issue.
- Warnings from old gems (sassc/mail/rubocop plugin interactions) remain and are not in this iteration’s scope.
